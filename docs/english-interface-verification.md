# Проверка английского интерфейса

Дата: 2026-09-25. macOS 26.7 (25G229), Chrome 153.0.8010.53, unpacked extension в отдельном тестовом профиле. Проверка через Playwright/CDP; popup открыт как страница расширения с viewport 360 × 600. Для проверки языка заданы CDP locale и Accept-Language `ru-RU`; `navigator.language` возвращал `ru-RU`. Язык ОС и нативных окон Chrome не менялся.

## Результаты

- Popup, настройки, доступные имена, подсказки, статусы и собственные ошибки — на английском; HTML объявляет `lang=en`. Светлая и тёмная темы просмотрены на технических снимках, действия доступны, горизонтального переполнения popup нет. Кнопка эмодзи остаётся слева от label.
- Enter открывает пикер с кнопки, Tab перемещает фокус, Escape закрывает его и возвращает фокус на исходную кнопку. Поиск `light bulb` находит 💡, категории и доступные имена английские. Выбор 🚀 сохраняется через worker и читается после повторного открытия из `chrome.storage.sync`.
- Первый запуск пикера с пустой IndexedDB выполнен при `context.setOffline(true)`. Запросы ограничены ресурсами `chrome-extension://`, включая `i18n/en.js` и `en.json`; внешних запросов каталога и ошибок страницы не обнаружено.
- После удаления только английской базы в тестовом профиле загрузка `en.json` искусственно отклонена через подмену `fetch`: показано `Could not load emoji. Try again.` и `Retry loading`. После восстановления `fetch` повтор успешно загружает каталог без сети.
- Для перехода создана настоящая русская база через vendor Database и исходный `ru/cldr-native/data.json` версии 1.8.0 из закреплённого архива. Данные поданы тестовой подменой `fetch`, без возвращения русского файла в расширение. Поиск `лампочка` в старой базе находит 💡. При отсутствующей английской базе новый пикер загружает английский каталог и находит `light bulb`; обе базы сосуществуют. История пикера может начинаться заново, выбранные эмодзи labels хранятся отдельно.
- Сохранённый label `вопрос`, ❓ и цвет `#123456` остаются без перевода. Открытие/закрытие пикера не меняет настройки labels; переключение темы меняет только тему. На локально перехваченном GitHub review-fixture вставка даёт `❓ вопрос: Черновик`.
- Корпоративный профиль GitLab сохраняет адрес, кириллическую маску `/группа/*` и CSS с комментарием `/* заметка */`. Настройки показывают английское предупреждение предварительной поддержки и `No access. Allow site access to continue.`. GitHub показывает `Site access granted.`. Невалидный адрес даёт `Site URL: enter a full HTTP(S) site URL.`, блокирует запрос доступа и не меняет сохранённую конфигурацию.
- Review-fixture без подходящего места панели показывает английскую диагностику, `Open profile settings` открывает профиль GitHub, `Close` закрывает уведомление. Добавление подходящего form восстанавливает панель; комментарий никуда не отправлялся.

## Автоматические проверки и границы

`npm test`: 109 тестов. Регрессии покрывают кириллические labels, Unicode-эмодзи, цвета, дубликаты, порядок, пустой список, отключённые эмодзи, тему, корпоративные настройки/CSS, отсутствие миграционных записей, черновики и выделение, поздние ответы, отказ доступа, ошибки и повтор сохранения. Vendor-проверки сверяют версии, SHA-256, лицензии и локальные зависимости.

`make package` и аудит ZIP проверяют английские ресурсы, лицензии и отсутствие старых `ru.json`/`ru_RU.js`. Основные спецификации и change проверяются OpenSpec в строгом режиме.

Нативные окна разрешений и выбора цвета, текст сайтов и внешние сообщения браузерных API не переводятся расширением. Отказ разрешений проверен автотестом; новый доступ к реальному корпоративному сайту не выдавался. Review-fixture проверяет интеграцию content script, а не актуальность DOM всех поддерживаемых сайтов. Технические снимки использованы только для приёмки; README и публикационные скриншоты относятся к следующему change.
