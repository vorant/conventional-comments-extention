# Профили сайтов: реализация и проверка

Дата обновления: 2026-09-21.

## Источники и границы проверки

- GitHub: DOM-признаки из [ранее выполненной проверки](github-dom-notes.md); текущая регрессия проверяется локальными тестами, повторная проверка живого сайта не выполнялась.
- GitLab: поля `name="note[note]"`, `.js-note-text` и `data-testid="reply-field"` описаны в [исходном компоненте GitLab](https://gitlab.com/gitlab-org/gitlab/-/raw/master/app/assets/javascripts/notes/components/note_form.vue). Профиль предназначен для textarea в Markdown-режиме. Обёртка и фактическое поведение сайта требуют ручной проверки.
- Bitbucket: [документация Atlassian](https://support.atlassian.com/bitbucket-cloud/docs/review-code-in-a-pull-request/) описывает визуальный редактор. Селекторы `.ProseMirror[contenteditable="true"]` и `.ak-editor-content-area, .akEditor, form` — предварительные предположения, не подтверждённый DOM Bitbucket. При несовпадении используйте диагностику и измените профиль.
- `test/fixtures/editors.html` — синтетические примеры, не снимки сайтов. Корпоративный пример моделирует два независимых комментария; корпоративная версия GitLab/Bitbucket не проверена.
- По решению пользователя реальные проверки GitLab/Bitbucket выполняет пользователь. Успех локальных тестов не подтверждает отправку текста этими сайтами.

## Разрешения Chrome

Используются [permissions.request / contains](https://developer.chrome.com/docs/extensions/reference/api/permissions) и [scripting.registerContentScripts](https://developer.chrome.com/docs/extensions/reference/api/scripting). Запрос доступа вызывается непосредственно нажатием кнопки пользователя. Динамическая регистрация доступна с Chrome 96; минимальная версия расширения — Chrome 102 с используемыми Promise API.

GitHub имеет постоянный доступ. Скрипт запускается на GitHub origin для поддержки SPA-переходов, но панель ограничена маской PR. Другие сайты требуют отдельного разрешения. Chrome разрешает доступ к хосту на всех портах; внутри расширения профиль дополнительно проверяет точный origin, включая порт. Изменение адреса и восстановление профиля не отзывают разрешения Chrome автоматически. Все три профиля включены постоянно. Доступ можно отозвать в настройках расширения Chrome.

Service worker синхронизирует регистрации при запуске, установке, изменении профилей и разрешений. Снятие регистрации само по себе не удаляет уже внедрённый UI: активным вкладкам отдельно отправляется команда очистки. Не доступные для связи документы очищаются после перезагрузки.

## Вставка текста

Textarea использует нативный setter и всплывающий `input`, чтобы управляемый редактор получил изменение. Для визуального редактора используется экспериментальная браузерная команда `insertText` в начале выделения: расширение не заменяет HTML целиком. Совместимость этой команды с конкретным редактором, его историей undo и отправкой требует проверки. Если операция отклонена, появляется сообщение; принудительная подмена HTML не выполняется.

Селекторы работают в основном документе. Закрытый Shadow DOM и редакторы внутри iframe не поддерживаются. Пользовательский JavaScript не выполняется.

## Локальные проверки

`npm test` проверяет:

- выбор профиля, точный адрес, маски и фиксированный порядок при пересечении, совместимость старых данных, сохранение и сброс;
- расположение панели, несколько комментариев, динамическое появление и удаление полей, поздний anchor, SPA-переходы;
- содержимое textarea, курсор, фокус и `input`, отсутствие повторного префикса;
- уведомления, их закрытие, подавление повторов и восстановление;
- автосохранение полей popup, ошибки ввода и записи, быстрый ввод, задержанные ответы, смену профиля и сброс во время записи;
- жизненный цикл worker с mock Chrome API: разрешения, отзыв, повторная регистрация и подключение, очистку старых регистраций и ошибки;
- регрессию настроек labels и темы.

DOM-стенд не рассчитывает геометрию, а API mocks не запускают настоящий Chrome. Визуальная проверка и проверка реального жизненного цикла MV3 остаются отдельными пунктами приёмки.

## Ручная приёмка GitLab и Bitbucket

1. Перезагрузите unpacked extension. В popup откройте «Сайты и размещение панели», выберите профиль и разрешите доступ к сайту.
2. Откройте MR/PR и поле комментария к строке. Для GitLab используйте Markdown-режим.
3. Если панель не появилась, проверьте доступ, адрес, маски и CSS-селектор редактора. Автоматическое уведомление о месте панели позволяет перейти к настройкам профиля. Внутренние контейнеры и тип редактора определяются предустановкой.
4. Введите черновик, нажмите label. Проверьте сохранение текста и форматирования, положение курсора и реакцию кнопки отправки. Проверьте повторный клик и undo для визуального редактора.
5. Самостоятельно проверьте отправку тестового комментария в подходящем репозитории и отмену черновика.
6. Выберите положение снизу, дождитесь «Сохранено» и проверьте два открытых комментария.
7. Проверьте быстрый ввод, смену профиля, закрытие и повторное открытие popup. Некорректное поле должно показывать ошибку без замены рабочей конфигурации. Кнопка «Восстановить» возвращает предустановку даже во время записи.
8. Для корпоративного сайта измените адрес, пути и селектор соответствующего встроенного профиля. Адаптер менять нельзя: Bitbucket Data Center с textarea вместо визуального редактора Cloud этой предустановкой не поддерживается.

## Совместимость хранилища

Эффективная конфигурация содержит только GitHub, GitLab и Bitbucket в этом порядке. Схема остаётся `schemaVersion: 1`. Старые `custom` сохраняются без применения; чтение не записывает миграцию. Для встроенных профилей принимаются только допустимые `origin`, `paths`, `editorSelector` и `placement` (`before`/`after`). Другие поля берутся из defaults. Устаревшее положение или неверное отдельное поле получает значение по умолчанию. Сохранение и сброс неизвестного id запрещены; неизвестная версия схемы не перезаписывается.

Popup отправляет каждый корректный снимок сразу в последовательную очередь worker, без debounce. Ответы не перерисовывают поля; черновики и статусы учитываются отдельно по профилю и версии. Кнопка доступа работает только для подтверждённого снимка. После ошибки записи повтор возможен изменением поля. Сброс упорядочен после предыдущих записей, новые изменения идут после сброса.

Откат версии сохраняет доступ к прежним custom-данным, но изменённые или восстановленные overrides автоматически не возвращаются. Labels и тема не затрагиваются.
