# firefox-local Specification

## Purpose

Обеспечивает существующий рабочий процесс Conventional Comments в Firefox desktop при локальной временной установке, с сохранением настроек активной установки и контролем доступа к сайтам.

## Requirements

### Requirement: Существующий интерфейс в Firefox
Расширение SHALL предоставлять в Firefox desktop поведение существующих спецификаций github-review-comments, popup-label-management, options-page, site-profiles, profile-diagnostics и interface-language. GitLab и Bitbucket SHALL сохранять статус preview; поддержка новых сайтов и редакторов не добавляется.

#### Scenario: Комментарии GitHub
- **WHEN** пользователь разрешил GitHub и открывает поддерживаемые редакторы комментариев в PR, включая динамическую навигацию
- **THEN** каждый редактор получает одну панель, выбранный префикс с эмодзи вставляется без потери текста, а курсор, обновление редактора и удаление панели соответствуют существующему поведению

#### Scenario: Popup и настройки
- **WHEN** пользователь меняет labels, порядок, цвета, эмодзи, тему, профиль или CSS
- **THEN** изменения сохраняются и применяются по существующим контрактам, Settings открывает нужную страницу, а шрифт и emoji-ресурсы загружаются из пакета

### Requirement: Настройки активной установки Firefox
Расширение SHALL сохранять подтверждённые настройки между открытиями popup, перезапусками фонового контекста и Reload активной временной установки. Оно SHALL NOT обещать перенос настроек из других браузеров или восстановление после удаления временной установки.

#### Scenario: Повторное открытие и Reload
- **WHEN** пользователь дожидается подтверждения сохранения, закрывает popup, перезапускает фоновый контекст либо выполняет Reload расширения
- **THEN** labels, тема, профили и CSS сохраняются, а после обновления вкладки панели используют сохранённые значения

#### Scenario: Ошибка сохранения
- **WHEN** API хранения возвращает ошибку при редактировании labels или профиля
- **THEN** интерфейс сообщает об ошибке по существующему контракту и не подтверждает успешное сохранение

#### Scenario: Независимость браузеров
- **WHEN** пользователь меняет настройки Firefox
- **THEN** данные установленного расширения Chrome и Safari не изменяются

### Requirement: Фактический доступ к сайтам Firefox
Расширение SHALL применять профили только на соответствующих страницах при фактическом разрешении доступа к сайту. Сохранение профиля SHALL NOT заменять выдачу разрешения; отказ, отзыв и ошибка регистрации SHALL NOT отображаться как успешное подключение.

#### Scenario: Отказ в доступе
- **WHEN** пользователь сохраняет корпоративный адрес профиля, но отклоняет запрос доступа
- **THEN** настройки показывают отсутствие доступа и панель на этом сайте не добавляется

#### Scenario: Выдача и отзыв
- **WHEN** пользователь выдаёт разрешение сайту, а затем отзывает его
- **THEN** после выдачи панель работает без дубликатов, после отзыва новые панели не добавляются, а существующий UI удаляется в доступных активных контекстах

#### Scenario: Ошибка подключения
- **WHEN** браузер отклоняет регистрацию скриптов для разрешённого профиля
- **THEN** ошибка доводится до интерфейса по существующему контракту и подключение не подтверждается как успешное
