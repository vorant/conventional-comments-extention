# github-review-comments Specification

## Purpose

Помогает ревьюерам GitHub Pull Requests быстрее оформлять комментарии к строкам кода в формате Conventional Comments, не заменяя стандартный интерфейс ревью GitHub.

## Requirements

### Requirement: Пользователь может переключить тему popup

Расширение SHALL предоставлять в popup переключатель между светлой и темной темой и SHALL сохранять выбранную тему между открытиями popup.

#### Scenario: Новый пользователь открывает popup

- **WHEN** пользователь открывает popup до выбора темы
- **THEN** popup отображается в светлой теме

#### Scenario: Пользователь включает темную тему

- **WHEN** пользователь переключает тему popup на темную
- **THEN** popup отображается в темной теме
- **AND** расширение сохраняет выбранную тему

#### Scenario: Пользователь возвращает светлую тему

- **WHEN** пользователь переключает тему popup на светлую
- **THEN** popup отображается в светлой теме
- **AND** расширение сохраняет выбранную тему

#### Scenario: Пользователь повторно открывает popup

- **WHEN** пользователь ранее выбрал темную тему и снова открывает popup
- **THEN** popup отображается в сохраненной темной теме

### Requirement: Пользователь может управлять списком labels в popup

Расширение SHALL предоставлять popup, в котором пользователь может просматривать, редактировать, удалять и добавлять labels, используемые панелью Conventional Comments. Popup SHALL использовать иконки для действий, где это уместно; удаление label SHALL быть доступно через красную icon-only кнопку корзины с доступным именем для assistive technologies. Иконки popup SHALL отображаться без требования установить Nerd Font в системе пользователя.

#### Scenario: Новый пользователь открывает popup

- **WHEN** пользователь открывает popup расширения до изменения настроек
- **THEN** popup показывает labels `praise`, `nitpick`, `suggestion`, `issue`, `todo`, `question`, `thought`, `chore`, `note`

#### Scenario: Пользователь редактирует label

- **WHEN** пользователь меняет текст существующего label в popup
- **THEN** расширение сохраняет новый текст label для последующего использования в панели GitHub Pull Request comments

#### Scenario: Пользователь добавляет label

- **WHEN** пользователь добавляет новый непустой label в popup
- **THEN** расширение сохраняет этот label в пользовательском списке

#### Scenario: Пользователь удаляет label

- **WHEN** пользователь нажимает красную иконку корзины у label в popup
- **THEN** расширение больше не показывает этот label в пользовательском списке

#### Scenario: Nerd Font не установлен в системе

- **WHEN** пользователь открывает popup на системе без установленного Nerd Font
- **THEN** popup показывает иконки действий с помощью шрифта, поставляемого вместе с расширением

#### Scenario: Пользователь закрывает и снова открывает браузер

- **WHEN** пользователь изменил список labels и позже снова открывает popup расширения
- **THEN** popup показывает ранее сохраненный пользовательский список labels

### Requirement: Пользователь может менять порядок labels в popup

Расширение SHALL позволять пользователю менять порядок labels в popup через drag-and-drop и SHALL сохранять новый порядок для последующего отображения в popup и панели GitHub Pull Request comments. Во время перетаскивания popup SHALL показывать preview нового порядка до отпускания элемента, а только строки в диапазоне между предыдущей preview-позицией и новой целевой позицией SHALL визуально сдвигаться с анимацией.

#### Scenario: Пользователь перетаскивает label выше другого label

- **WHEN** пользователь перетаскивает label `question` перед label `suggestion` в popup
- **THEN** popup показывает `question` перед `suggestion` до отпускания элемента
- **AND** строка `suggestion` визуально сдвигается на следующую позицию
- **AND** после отпускания элемента расширение сохраняет новый порядок labels

#### Scenario: Пользователь перетаскивает label ниже другого label

- **WHEN** пользователь перетаскивает второй label на четвертую позицию в popup
- **THEN** popup показывает preview нового порядка до отпускания элемента
- **AND** только второй, третий и четвертый labels получают визуальную анимацию переноса
- **AND** остальные labels остаются без анимации переноса

#### Scenario: Пользователь продолжает перетаскивать label после preview

- **WHEN** пользователь перетаскивает второй label на четвертую позицию в popup
- **AND** не отпуская label, переносит его с четвертой preview-позиции на седьмую позицию
- **THEN** popup показывает preview нового порядка до отпускания элемента
- **AND** только четвертый, пятый, шестой и седьмой labels получают визуальную анимацию переноса
- **AND** первый, второй, третий labels и labels после седьмой позиции остаются без анимации переноса

#### Scenario: Пользователь повторно открывает popup после сортировки

- **WHEN** пользователь изменил порядок labels и позже снова открывает popup
- **THEN** popup показывает labels в ранее сохраненном порядке

#### Scenario: Пользователь открывает поле комментария после сортировки

- **WHEN** пользователь изменил порядок labels в popup и открывает поле комментария к строке кода в GitHub Pull Request
- **THEN** панель labels показывает labels в сохраненном порядке

#### Scenario: Пользователь перетаскивает label без изменения позиции

- **WHEN** пользователь начинает перетаскивать label, но отпускает его в исходной позиции
- **THEN** порядок labels не меняется

#### Scenario: Пользователь отменяет перенос после preview

- **WHEN** пользователь начинает перетаскивать label, видит preview нового порядка и отменяет перенос до отпускания над новой позицией
- **THEN** popup возвращает labels к исходному порядку

#### Scenario: Пользователь видит drag handle в любой теме

- **WHEN** пользователь открывает popup в светлой или темной теме
- **THEN** каждая строка label показывает иконку drag handle, подходящую для текущей темы

### Requirement: Расширение имеет собственную иконку в Chrome UI

Расширение SHALL объявлять собственную иконку для Chrome extension UI, включая toolbar/action icon и manifest icons.

#### Scenario: Пользователь видит расширение в панели Chrome

- **WHEN** пользователь устанавливает расширение как unpacked extension
- **THEN** Chrome показывает для расширения собственную иконку вместо дефолтной иконки расширения

#### Scenario: Chrome запрашивает стандартные размеры иконки

- **WHEN** Chrome отображает расширение в местах, где нужны размеры `16`, `32`, `48` или `128`
- **THEN** manifest ссылается на существующие icon assets этих размеров

### Requirement: Панель labels появляется у поля комментария к строке кода

Расширение SHALL показывать панель с сохраненными Conventional Comments labels рядом со стандартным полем ввода комментария, которое GitHub открывает для строки кода в Pull Request. Если пользовательский список еще не сохранен, расширение SHALL использовать стандартные labels `praise`, `nitpick`, `suggestion`, `issue`, `todo`, `question`, `thought`, `chore`, `note`.

#### Scenario: Открыто поле комментария к строке

- **WHEN** пользователь открывает стандартное поле комментария к строке кода в GitHub Pull Request
- **THEN** расширение показывает рядом с этим полем панель доступных сохраненных labels

#### Scenario: Поле комментария еще не открыто

- **WHEN** пользователь находится на странице Pull Request без открытого поля комментария к строке
- **THEN** расширение не показывает отдельную панель labels вне контекста поля комментария

#### Scenario: Список labels пустой

- **WHEN** пользователь удалил все labels в popup и открывает поле комментария к строке кода в GitHub Pull Request
- **THEN** расширение не показывает пустую панель labels рядом с этим полем

### Requirement: Пользователь может вставить label в начало комментария

Расширение SHALL вставлять выбранный из отображаемой панели Conventional Comments label в начало текущего текста комментария.

#### Scenario: Комментарий пустой

- **WHEN** пользователь нажимает label `suggestion`
- **THEN** поле комментария начинается с текста `suggestion: `

#### Scenario: В комментарии уже есть текст

- **WHEN** пользователь нажимает label `question` в поле с уже введенным текстом
- **THEN** поле комментария начинается с текста `question: `, а ранее введенный текст сохраняется после этого префикса

#### Scenario: Пользовательский label содержит emoji

- **WHEN** пользователь нажимает сохраненный label `idea💡`
- **THEN** поле комментария начинается с текста `idea💡: `

#### Scenario: Пользовательский label заменяет стандартный label

- **WHEN** пользователь переименовал `suggestion` в `proposal` и нажимает label `proposal`
- **THEN** поле комментария начинается с текста `proposal: `

### Requirement: MVP ограничен GitHub Pull Requests

Расширение SHALL работать только в контексте GitHub Pull Requests и SHALL NOT изменять интерфейсы GitLab Merge Requests или Bitbucket Pull Requests в рамках MVP.

#### Scenario: Пользователь открывает GitHub Pull Request

- **WHEN** пользователь открывает страницу GitHub Pull Request с интерфейсом review comments
- **THEN** расширение может добавить панель labels к открытым полям комментариев к строкам кода

#### Scenario: Пользователь открывает GitLab или Bitbucket

- **WHEN** пользователь открывает страницу GitLab Merge Request или Bitbucket Pull Request
- **THEN** расширение не добавляет панель labels

### Requirement: Стандартное поведение GitHub сохраняется

Расширение SHALL сохранять стандартный процесс написания, отправки и отмены review comment в GitHub.

#### Scenario: Пользователь отправляет комментарий

- **WHEN** пользователь добавляет label через расширение и отправляет комментарий стандартной кнопкой GitHub
- **THEN** комментарий отправляется через обычный механизм GitHub

#### Scenario: Пользователь отменяет комментарий

- **WHEN** пользователь закрывает или отменяет поле комментария стандартным действием GitHub
- **THEN** расширение не препятствует закрытию или отмене комментария
