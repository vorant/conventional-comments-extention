# github-review-comments Specification

## Purpose

Помогает ревьюерам GitHub Pull Requests быстрее оформлять комментарии к строкам кода в формате Conventional Comments, не заменяя стандартный интерфейс ревью GitHub.

## Requirements

### Requirement: Панель labels появляется у поля комментария к строке кода

Расширение SHALL показывать панель с Conventional Comments labels рядом со стандартным полем ввода комментария, которое GitHub открывает для строки кода в Pull Request.

#### Scenario: Открыто поле комментария к строке

- **WHEN** пользователь открывает стандартное поле комментария к строке кода в GitHub Pull Request
- **THEN** расширение показывает рядом с этим полем панель доступных Conventional Comments labels

#### Scenario: Поле комментария еще не открыто

- **WHEN** пользователь находится на странице Pull Request без открытого поля комментария к строке
- **THEN** расширение не показывает отдельную панель labels вне контекста поля комментария

### Requirement: Пользователь может вставить label в начало комментария

Расширение SHALL вставлять выбранный Conventional Comments label в начало текущего текста комментария.

#### Scenario: Комментарий пустой

- **WHEN** пользователь нажимает label `suggestion`
- **THEN** поле комментария начинается с текста `suggestion: `

#### Scenario: В комментарии уже есть текст

- **WHEN** пользователь нажимает label `question` в поле с уже введенным текстом
- **THEN** поле комментария начинается с текста `question: `, а ранее введенный текст сохраняется после этого префикса

### Requirement: MVP ограничен GitHub Pull Requests

Расширение SHALL работать только в контексте GitHub Pull Requests и SHALL NOT изменять интерфейсы GitLab Merge Requests или Bitbucket Pull Requests в рамках MVP.

#### Scenario: Пользователь открывает GitHub Pull Request

- **WHEN** пользователь открывает страницу GitHub Pull Request с интерфейсом review comments
- **THEN** расширение может добавить панель labels к открытым полям комментариев к строкам кода

#### Scenario: Пользователь открывает GitLab или Bitbucket

- **WHEN** пользователь открывает страницу GitLab Merge Request или Bitbucket Pull Request
- **THEN** расширение не добавляет панель labels

### Requirement: Стандартное поведение GitHub сохраняется

Расширение SHALL сохранять стандартный процесс написания, отправки и отмены review comment в GitHub.

#### Scenario: Пользователь отправляет комментарий

- **WHEN** пользователь добавляет label через расширение и отправляет комментарий стандартной кнопкой GitHub
- **THEN** комментарий отправляется через обычный механизм GitHub

#### Scenario: Пользователь отменяет комментарий

- **WHEN** пользователь закрывает или отменяет поле комментария стандартным действием GitHub
- **THEN** расширение не препятствует закрытию или отмене комментария
