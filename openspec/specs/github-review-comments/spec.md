# github-review-comments Specification

## Purpose

Помогает ревьюерам GitHub Pull Requests быстрее оформлять комментарии к строкам кода в формате Conventional Comments, не заменяя стандартный интерфейс ревью GitHub.

## Requirements

### Requirement: Панель labels появляется у поля комментария к строке кода

Расширение SHALL показывать панель с сохраненными Conventional Comments labels рядом со стандартным полем ввода комментария, которое GitHub открывает для строки кода в Pull Request. Если пользовательский список еще не сохранен, расширение SHALL использовать стандартные labels `praise`, `nitpick`, `suggestion`, `issue`, `todo`, `question`, `thought`, `chore`, `note`.

#### Scenario: Открыто поле комментария к строке

- **WHEN** пользователь открывает стандартное поле комментария к строке кода в GitHub Pull Request
- **THEN** расширение показывает рядом с этим полем панель доступных сохраненных labels

#### Scenario: Поле комментария еще не открыто

- **WHEN** пользователь находится на странице Pull Request без открытого поля комментария к строке
- **THEN** расширение не показывает отдельную панель labels вне контекста поля комментария

#### Scenario: Список labels пустой

- **WHEN** пользователь удалил все labels в popup и открывает поле комментария к строке кода в GitHub Pull Request
- **THEN** расширение не показывает пустую панель labels рядом с этим полем

### Requirement: Пользователь может вставить label в начало комментария

Расширение SHALL вставлять выбранный из отображаемой панели Conventional Comments label в начало текущего текста комментария.

#### Scenario: Комментарий пустой

- **WHEN** пользователь нажимает label `suggestion`
- **THEN** поле комментария начинается с текста `suggestion: `

#### Scenario: В комментарии уже есть текст

- **WHEN** пользователь нажимает label `question` в поле с уже введенным текстом
- **THEN** поле комментария начинается с текста `question: `, а ранее введенный текст сохраняется после этого префикса

#### Scenario: Пользовательский label содержит emoji

- **WHEN** пользователь нажимает сохраненный label `idea💡`
- **THEN** поле комментария начинается с текста `idea💡: `

#### Scenario: Пользовательский label заменяет стандартный label

- **WHEN** пользователь переименовал `suggestion` в `proposal` и нажимает label `proposal`
- **THEN** поле комментария начинается с текста `proposal: `

### Requirement: Стандартное поведение GitHub сохраняется

Расширение SHALL сохранять стандартный процесс написания, отправки и отмены review comment в GitHub.

#### Scenario: Пользователь отправляет комментарий

- **WHEN** пользователь добавляет label через расширение и отправляет комментарий стандартной кнопкой GitHub
- **THEN** комментарий отправляется через обычный механизм GitHub

#### Scenario: Пользователь отменяет комментарий

- **WHEN** пользователь закрывает или отменяет поле комментария стандартным действием GitHub
- **THEN** расширение не препятствует закрытию или отмене комментария

### Requirement: Совместимость существующего GitHub-профиля

Расширение SHALL сохранять прежнее поведение панели GitHub Pull Requests после обновления без повторного ввода селекторов, потери labels или изменения темы popup. Пользователь SHALL иметь возможность переопределить размещение и селекторы через настройки профиля.

#### Scenario: Обновление существующей установки
- **WHEN** пользователь обновляет расширение и открывает стандартный комментарий к строке GitHub Pull Request
- **THEN** встроенный профиль показывает панель с прежними labels и порядком без дополнительной настройки

#### Scenario: Переопределение GitHub
- **WHEN** пользователь сохраняет собственное размещение панели GitHub
- **THEN** расширение использует выбранное размещение и сохраняет обычные вставку префикса, отправку и отмену комментария
