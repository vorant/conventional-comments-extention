# options-page Specification

## Purpose

Описывает отдельную страницу настроек расширения, на которой пользователь редактирует профили сайтов, управляет доступом и видит состояние сохранения.

## Requirements

### Requirement: Отдельная страница настроек

Расширение SHALL предоставлять страницу настроек в отдельной вкладке Chrome, доступную из popup и стандартного интерфейса управления расширениями. Форма профилей SHALL быть видима сразу без раскрытия дополнительного раздела. Закрытие popup SHALL NOT закрывать страницу настроек.

#### Scenario: Открытие из Chrome
- **WHEN** пользователь выбирает настройки расширения в интерфейсе Chrome
- **THEN** открывается отдельная вкладка с формой профилей

#### Scenario: Открытие без указания профиля
- **WHEN** пользователь открывает страницу без идентификатора профиля либо с неизвестным идентификатором
- **THEN** выбран профиль GitHub

#### Scenario: Закрытие popup
- **WHEN** пользователь открыл настройки из popup и popup закрылся
- **THEN** форма остаётся доступна в отдельной вкладке

### Requirement: Форма встроенных профилей

Страница SHALL предоставлять выбор ровно трёх профилей с фиксированными названиями GitHub, GitLab и Bitbucket и редактирование адреса, масок страниц, одного CSS-селектора редактора и положения панели «Above editor» или «Below editor», а также CSS панели в блоке «Panel styles». Страница SHALL NOT предоставлять создание, переименование, удаление или выключение профилей, поля контейнера, типа редактора или элемента размещения. Синтаксически неверные адрес и CSS-селектор SHALL показывать ошибку без замены последней корректной конфигурации.

#### Scenario: Открытие формы
- **WHEN** пользователь открывает настройки профилей
- **THEN** доступны три встроенных профиля и только перечисленные редактируемые поля
- **AND** доступны предупреждения о предварительной поддержке GitLab и Bitbucket и Markdown-режиме GitLab

#### Scenario: Невалидный ввод
- **WHEN** пользователь вводит неверный адрес или синтаксически неверный CSS-селектор
- **THEN** форма показывает ошибку и оставляет введённое значение для исправления
- **AND** последняя корректная конфигурация сохраняется

### Requirement: Восстановление профиля

Кнопка «Reset profile» SHALL возвращать настройки выбранного профиля к предустановленным, включая CSS панели, без изменения других профилей, labels и темы.

#### Scenario: Сброс выбранного профиля
- **WHEN** пользователь нажимает «Reset profile»
- **THEN** выбранный профиль получает предустановленные значения, а остальные настройки сохраняются

### Requirement: Предоставление доступа со страницы настроек

Страница SHALL предоставлять отдельную кнопку «Allow site access» для доступа к сайту текущего подтверждённого сохранённого профиля. Автосохранение SHALL NOT запрашивать доступ. Кнопка SHALL быть недоступна при невалидном вводе, незавершённом сохранении или ошибке записи. Отказ SHALL NOT удалять сохранённые настройки или отображаться как успешное подключение.

#### Scenario: Доступ после сохранения
- **WHEN** пользователь нажимает кнопку доступа для подтверждённого профиля
- **THEN** запрос относится к сохранённому адресу этого профиля

#### Scenario: Несохранённый адрес
- **WHEN** адрес изменён, но ещё не подтверждено его сохранение
- **THEN** запрос доступа недоступен

#### Scenario: Отказ в доступе
- **WHEN** пользователь отклоняет запрос доступа
- **THEN** форма сообщает об отсутствии доступа и сохраняет настройки

### Requirement: Общая тема страницы настроек и popup

Страница настроек SHALL использовать общую сохранённую тему popup, светлую по умолчанию. Изменение темы в popup SHALL обновлять уже открытую страницу настроек без перезагрузки.

#### Scenario: Первое открытие
- **WHEN** тема ещё не выбиралась
- **THEN** страница настроек отображается в светлой теме

#### Scenario: Сохранённая тёмная тема
- **WHEN** пользователь открывает настройки с сохранённой тёмной темой
- **THEN** форма отображается в тёмной теме

#### Scenario: Смена темы при открытых настройках
- **WHEN** пользователь переключает тему в popup при открытой странице настроек
- **THEN** страница применяет новую тему без перезагрузки и потери черновика

### Requirement: Автосохранение настроек профиля

Каждое корректное изменение редактируемых настроек SHALL автоматически отправляться на сохранение без кнопки «Save». Интерфейс SHALL различать сохранение, успешное сохранение и ошибку. Некорректный ввод SHALL оставаться доступным для исправления, не заменяя последнюю корректную конфигурацию. Асинхронные операции SHALL NOT терять более новые изменения или применять изменения к другому профилю.

#### Scenario: Изменение и повторное открытие
- **WHEN** пользователь меняет корректное поле и получает подтверждение сохранения
- **THEN** новое значение применяется и остаётся доступным после повторного открытия страницы настроек

#### Scenario: Быстрый ввод и переключение профиля
- **WHEN** пользователь вносит несколько корректных изменений до завершения сохранения и переключает профиль
- **THEN** сохраняются последние корректные значения исходного профиля без изменения формы другого профиля

#### Scenario: Ошибка ввода или записи
- **WHEN** поле невалидно или запись настроек завершается ошибкой
- **THEN** интерфейс показывает ошибку, не сообщает об успешном сохранении и позволяет исправить либо повторить действие

#### Scenario: Восстановление во время сохранения
- **WHEN** пользователь нажимает «Reset profile» при незавершённом автосохранении
- **THEN** итогом становятся предустановленные настройки выбранного профиля, а поздний ответ не возвращает прежние значения

### Requirement: Редактор стилей панели

Блок «Panel styles» SHALL содержать многострочное редактируемое поле CSS панели и кнопок выбранного профиля, кроме приоритетной раскраски labels. При отсутствии переопределения поле SHALL показывать стандартный CSS расширения, а не пустое поле или placeholder. Изменения SHALL автоматически сохраняться по контракту автосохранения и оставаться доступными после повторного открытия. Пустой CSS SHALL означать отсутствие правил CSS профиля, но SHALL NOT отключать цвет текста, фона и рамки labels. Восстановление стандартов выполняется отдельной кнопкой. Подсказка SHALL объяснять приоритет цветов labels из popup над CSS профиля. CSS SHALL обрабатываться по правилам браузера: неподдерживаемые или ошибочные правила могут игнорироваться, исходный текст SHALL сохраняться без потери при редактировании.

#### Scenario: Стандартные стили видны сразу
- **WHEN** пользователь открывает профиль без сохранённого CSS
- **THEN** поле содержит стандартный CSS панели и кнопок

#### Scenario: Независимое редактирование
- **WHEN** пользователь меняет CSS GitHub, дожидается сохранения и переключается на GitLab
- **THEN** GitLab показывает собственные стили, а при возврате GitHub показывает сохранённый текст

#### Scenario: Очистка поля
- **WHEN** пользователь удаляет весь текст CSS и дожидается сохранения
- **THEN** поле остаётся пустым после повторного открытия и стандартные правила геометрии панели автоматически не подставляются
- **AND** цвета labels продолжают применяться

#### Scenario: Незавершённое CSS-правило
- **WHEN** пользователь вводит промежуточный или неподдерживаемый CSS
- **THEN** введённый текст сохраняется, а применение правил следует поведению CSS-парсера браузера

### Requirement: Восстановление стилей выбранного профиля

Кнопка «Reset styles» в блоке «Panel styles» SHALL заменять CSS только выбранного профиля стандартными стилями и автоматически сохранять результат. Адрес, маски, селектор, положение панели, labels, тема и другие профили SHALL сохраняться. Действие SHALL сохранять несохранённые черновики остальных полей и работать при их невалидности. Поздние ответы предыдущих операций SHALL NOT отменять сброс или более поздние правки.

#### Scenario: Локальный сброс CSS
- **WHEN** пользователь нажимает «Reset styles» в блоке стилей GitLab
- **THEN** поле и панели GitLab получают стандартные стили, остальные настройки и стили GitHub/Bitbucket сохраняются

#### Scenario: Сброс при ошибке другого поля
- **WHEN** адрес в форме невалиден и пользователь восстанавливает стили
- **THEN** CSS восстанавливается, введённый адрес остаётся в форме для исправления, а сохранённый адрес не меняется

#### Scenario: Сброс во время записи
- **WHEN** пользователь восстанавливает стили во время сохранения предыдущего CSS
- **THEN** итогом становятся стандартные стили, а предыдущий ответ не возвращает старый CSS

### Requirement: Независимость цветов labels от сброса профиля

Отдельное восстановление CSS и полный сброс профиля SHALL сохранять общие цвета labels. Страница настроек SHALL направлять пользователя к popup для изменения этих цветов.

#### Scenario: Восстановление CSS
- **WHEN** пользователь меняет цвет label в popup и восстанавливает CSS выбранного профиля
- **THEN** выбранный цвет label сохраняется на панелях всех применимых профилей

#### Scenario: Полный сброс
- **WHEN** пользователь восстанавливает профиль целиком
- **THEN** профиль получает стандартные настройки, а выбранные цвета labels остаются прежними
