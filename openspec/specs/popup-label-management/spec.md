# popup-label-management Specification

## Purpose

Описывает поведение popup расширения для настройки темы и управления списком Conventional Comments labels, которые затем используются в popup и панели GitHub Pull Request comments.

## Requirements

### Requirement: Пользователь может переключить тему popup

Расширение SHALL предоставлять в popup переключатель между светлой и темной темой и SHALL сохранять выбранную тему между открытиями popup.

#### Scenario: Новый пользователь открывает popup

- **WHEN** пользователь открывает popup до выбора темы
- **THEN** popup отображается в светлой теме

#### Scenario: Пользователь включает темную тему

- **WHEN** пользователь переключает тему popup на темную
- **THEN** popup отображается в темной теме
- **AND** расширение сохраняет выбранную тему

#### Scenario: Пользователь возвращает светлую тему

- **WHEN** пользователь переключает тему popup на светлую
- **THEN** popup отображается в светлой теме
- **AND** расширение сохраняет выбранную тему

#### Scenario: Пользователь повторно открывает popup

- **WHEN** пользователь ранее выбрал темную тему и снова открывает popup
- **THEN** popup отображается в сохраненной темной теме

### Requirement: Пользователь может управлять списком labels в popup

Расширение SHALL предоставлять popup, в котором пользователь может просматривать, редактировать, удалять и добавлять labels, используемые панелью Conventional Comments. Popup SHALL использовать иконки для действий, где это уместно; удаление label SHALL быть доступно через красную icon-only кнопку корзины с доступным именем для assistive technologies. Иконки popup SHALL отображаться без требования установить Nerd Font в системе пользователя.

#### Scenario: Новый пользователь открывает popup

- **WHEN** пользователь открывает popup расширения до изменения настроек
- **THEN** popup показывает labels `praise`, `nitpick`, `suggestion`, `issue`, `todo`, `question`, `thought`, `chore`, `note`

#### Scenario: Пользователь редактирует label

- **WHEN** пользователь меняет текст существующего label в popup
- **THEN** расширение сохраняет новый текст label для последующего использования в панели GitHub Pull Request comments

#### Scenario: Пользователь добавляет label

- **WHEN** пользователь добавляет новый непустой label в popup
- **THEN** расширение сохраняет этот label в пользовательском списке

#### Scenario: Пользователь удаляет label

- **WHEN** пользователь нажимает красную иконку корзины у label в popup
- **THEN** расширение больше не показывает этот label в пользовательском списке

#### Scenario: Nerd Font не установлен в системе

- **WHEN** пользователь открывает popup на системе без установленного Nerd Font
- **THEN** popup показывает иконки действий с помощью шрифта, поставляемого вместе с расширением

#### Scenario: Пользователь закрывает и снова открывает браузер

- **WHEN** пользователь изменил список labels и позже снова открывает popup расширения
- **THEN** popup показывает ранее сохраненный пользовательский список labels

### Requirement: Пользователь может менять порядок labels в popup

Расширение SHALL позволять пользователю менять порядок labels в popup через drag-and-drop и SHALL сохранять новый порядок для последующего отображения в popup и панели GitHub Pull Request comments. Во время перетаскивания popup SHALL показывать preview нового порядка до отпускания элемента, а только строки в диапазоне между предыдущей preview-позицией и новой целевой позицией SHALL визуально сдвигаться с анимацией.

#### Scenario: Пользователь перетаскивает label выше другого label

- **WHEN** пользователь перетаскивает label `question` перед label `suggestion` в popup
- **THEN** popup показывает `question` перед `suggestion` до отпускания элемента
- **AND** строка `suggestion` визуально сдвигается на следующую позицию
- **AND** после отпускания элемента расширение сохраняет новый порядок labels

#### Scenario: Пользователь перетаскивает label ниже другого label

- **WHEN** пользователь перетаскивает второй label на четвертую позицию в popup
- **THEN** popup показывает preview нового порядка до отпускания элемента
- **AND** только второй, третий и четвертый labels получают визуальную анимацию переноса
- **AND** остальные labels остаются без анимации переноса

#### Scenario: Пользователь продолжает перетаскивать label после preview

- **WHEN** пользователь перетаскивает второй label на четвертую позицию в popup
- **AND** не отпуская label, переносит его с четвертой preview-позиции на седьмую позицию
- **THEN** popup показывает preview нового порядка до отпускания элемента
- **AND** только четвертый, пятый, шестой и седьмой labels получают визуальную анимацию переноса
- **AND** первый, второй, третий labels и labels после седьмой позиции остаются без анимации переноса

#### Scenario: Пользователь повторно открывает popup после сортировки

- **WHEN** пользователь изменил порядок labels и позже снова открывает popup
- **THEN** popup показывает labels в ранее сохраненном порядке

#### Scenario: Пользователь открывает поле комментария после сортировки

- **WHEN** пользователь изменил порядок labels в popup и открывает поле комментария к строке кода в GitHub Pull Request
- **THEN** панель labels показывает labels в сохраненном порядке

#### Scenario: Пользователь перетаскивает label без изменения позиции

- **WHEN** пользователь начинает перетаскивать label, но отпускает его в исходной позиции
- **THEN** порядок labels не меняется

#### Scenario: Пользователь отменяет перенос после preview

- **WHEN** пользователь начинает перетаскивать label, видит preview нового порядка и отменяет перенос до отпускания над новой позицией
- **THEN** popup возвращает labels к исходному порядку

#### Scenario: Пользователь видит drag handle в любой теме

- **WHEN** пользователь открывает popup в светлой или темной теме
- **THEN** каждая строка label показывает иконку drag handle, подходящую для текущей темы

### Requirement: Переход из popup к настройкам

Popup SHALL предоставлять кнопку с иконкой gear справа от переключателя темы, доступным именем и подсказкой «Настройки». Кнопка SHALL открывать страницу настроек расширения в отдельной вкладке. Popup SHALL содержать управление labels и темой без формы настройки профилей сайтов.

#### Scenario: Переход кнопкой gear
- **WHEN** пользователь активирует кнопку «Настройки» мышью или клавиатурой
- **THEN** открывается страница настроек расширения в отдельной вкладке либо активируется уже открытая страница

#### Scenario: Состав popup
- **WHEN** пользователь открывает popup
- **THEN** видны labels, управление ими, переключатель темы и gear справа от него
- **AND** форма профилей и раскрывающийся раздел «Сайты и размещение панели» отсутствуют

### Requirement: Выбор цвета label

Каждая существующая строка label в popup SHALL показывать текущий цвет и предоставлять пикер одного базового цвета с доступным названием, связанным с label, и клавиатурным доступом. Выбор SHALL автоматически сохраняться и SHALL NOT изменять текст, порядок или тему. Взаимодействие с пикером SHALL NOT начинать перетаскивание строки.

#### Scenario: Выбор и повторное открытие
- **WHEN** пользователь выбирает цвет и получает подтверждение сохранения
- **THEN** новый цвет применяется к label и остаётся выбранным после повторного открытия popup и браузера

#### Scenario: Доступность
- **WHEN** пользователь переходит к выбору цвета с клавиатуры или вспомогательной технологией
- **THEN** элемент доступен для взаимодействия и его название указывает соответствующий label

### Requirement: Стандартная палитра и совместимость

Расширение SHALL сразу назначать стандартным labels палитру: praise — зелёный, nitpick — серый, suggestion — синий, issue — красный, todo — оранжевый, question — фиолетовый, thought — сиреневый, chore — серо-коричневый, note — бирюзовый. Прежние сохранённые списки SHALL сохранять текст и порядок; известные стандартные названия SHALL получать эту палитру, остальные — нейтральный серый. Пустой список SHALL оставаться пустым. Любой новый label, добавленный пользователем, SHALL начинать с нейтрального серого до выбора цвета.

#### Scenario: Установка без настроек
- **WHEN** сохранённого списка labels нет
- **THEN** отображаются девять стандартных labels в прежнем порядке с указанной палитрой

#### Scenario: Прежние данные
- **WHEN** сохранён список строк со стандартными и пользовательскими названиями
- **THEN** сохраняются его состав и порядок, известные стандартные названия раскрашены по палитре, остальные нейтральны

#### Scenario: Пустой список
- **WHEN** прежде пользователь удалил все labels
- **THEN** обновление не возвращает стандартные labels

#### Scenario: Новый label
- **WHEN** пользователь добавляет непустой label, даже со стандартным названием
- **THEN** новая строка имеет нейтральный цвет и доступный пикер

#### Scenario: Повреждённый цвет
- **WHEN** запись label содержит допустимый текст и некорректный цвет
- **THEN** label сохраняет текст и позицию, а цвет заменяется нейтральным

### Requirement: Цвет принадлежит записи label

Переименование, перенос и повторное открытие SHALL сохранять выбранный цвет конкретной записи. Совпадающие названия SHALL NOT связывать цвета разных записей. Удаление SHALL удалять цвет вместе с записью. Отмена drag preview SHALL восстанавливать исходный порядок записей вместе с их цветами.

#### Scenario: Переименование и перенос
- **WHEN** пользователь переименовывает окрашенный label и перемещает его
- **THEN** цвет остаётся у этого label после сохранения и повторного открытия

#### Scenario: Совпадающие названия
- **WHEN** два labels имеют одинаковый текст и пользователь меняет цвет одного из них
- **THEN** цвет второго не меняется

#### Scenario: Отмена переноса
- **WHEN** пользователь отменяет перетаскивание после preview
- **THEN** исходный порядок и соответствие цветов восстанавливаются

### Requirement: Надёжное автосохранение цвета

Popup SHALL различать сохранение, успешное сохранение и ошибку записи. Быстрые изменения цвета и последующие изменения текста или порядка SHALL сохранять последний снимок без возврата к устаревшему ответу. Уже отправленное сохранение SHALL продолжаться после закрытия popup. При ошибке открытый popup SHALL сохранять текущий черновик и предоставлять повтор записи.

#### Scenario: Быстрый выбор
- **WHEN** пользователь быстро меняет цвет, затем текст или порядок labels
- **THEN** после успешного завершения сохраняется последний снимок с правильным соответствием текста и цвета

#### Scenario: Ошибка хранилища
- **WHEN** запись цвета отклоняется, в том числе из-за квоты
- **THEN** popup сообщает об ошибке, не выдаёт её за успех и позволяет повторить текущий снимок

#### Scenario: Закрытие popup
- **WHEN** popup закрывается после отправки изменения на сохранение
- **THEN** запись продолжает выполняться и при успешном завершении доступна после открытия

#### Scenario: Неизвестная версия данных
- **WHEN** хранилище содержит неизвестную версию настроек labels
- **THEN** popup сообщает об ошибке и не перезаписывает неизвестные данные автоматически

### Requirement: Выбор и удаление эмодзи label

Popup SHALL предоставлять для каждой записи готовый пикер Unicode-эмодзи с поиском, текущим выбором и действием «Без эмодзи». Пикер SHALL работать без сетевого доступа с русскоязычным интерфейсом и поиском по русским названиям. Управление SHALL быть доступно клавиатурой, иметь имя соответствующего label и SHALL NOT запускать drag-and-drop. Закрытие без выбора SHALL сохранять прежнее значение и возвращать фокус к вызвавшему элементу.

#### Scenario: Выбор символа
- **WHEN** пользователь находит эмодзи поиском и выбирает его
- **THEN** символ сохраняется у выбранной записи и показан после повторного открытия popup
- **AND** текст, цвет и порядок labels не меняются

#### Scenario: Минимализм для одной записи
- **WHEN** пользователь выбирает «Без эмодзи»
- **THEN** символ удаляется только у этой записи и не восстанавливается после перезапуска

#### Scenario: Закрытие и доступность
- **WHEN** пользователь открывает пикер клавиатурой и закрывает его Escape без выбора
- **THEN** значение не меняется, фокус возвращается на кнопку выбора и строка не перетаскивается

#### Scenario: Без сети
- **WHEN** пользователь впервые открывает пикер без подключения к сети
- **THEN** каталог и поиск работают из ресурсов расширения

### Requirement: Общее отключение эмодзи

Popup SHALL предоставлять сохраняемый переключатель «Показывать и вставлять эмодзи», включённый по умолчанию. Выключение SHALL скрывать символы на кнопках панелей и исключать их из будущей вставки для всех профилей, сохраняя индивидуальный выбор. В popup SHALL оставаться доступным редактирование выбранных символов даже при общем отключении.

#### Scenario: Отключение и восстановление
- **WHEN** пользователь выключает переключатель, перезапускает popup и затем включает его
- **THEN** до включения панели и будущие вставки не содержат отдельного эмодзи, а после включения используют сохранённый выбор
- **AND** записи с «Без эмодзи» остаются без символа

### Requirement: Значения эмодзи и совместимость данных

Расширение SHALL назначать стандартные эмодзи: praise 👍, nitpick 🔍, suggestion 💡, issue 🚨, todo ✅, question ❓, thought 💭, chore 🔧, note 📝. При первом чтении прежних данных без настроек эмодзи известные точные названия SHALL получать указанные символы, остальные — отсутствие символа. Состав, порядок, цвета, пустые списки и тема SHALL сохраняться. Новые записи, включая совпадающие со стандартными названиями, SHALL создаваться без эмодзи. Явно удалённый символ SHALL отличаться от отсутствующего поля прежней версии. Некорректный символ SHALL безопасно трактоваться как отсутствие эмодзи; неизвестная версия SHALL NOT автоматически перезаписываться.

#### Scenario: Обновление и первая установка
- **WHEN** пользователь открывает новую установку либо обновляет прежние строковые или цветовые настройки
- **THEN** стандартные названия получают согласованные символы, остальные остаются без них, прежний список и цвета сохраняются

#### Scenario: Новая запись и пустой список
- **WHEN** пользователь добавляет label в ранее пустой список
- **THEN** создаётся только новая запись без эмодзи, стандартный набор не восстанавливается

#### Scenario: Удалённый и некорректный символ
- **WHEN** сохранённая запись имеет явно пустой либо некорректный эмодзи
- **THEN** запись сохраняет текст и цвет и отображается без отдельного символа

### Requirement: Надёжное сохранение эмодзи

Эмодзи SHALL принадлежать записи, сохраняться при переименовании, переносе и отмене preview независимо от одинаковых названий. Изменения символов, общего переключателя, текста, цвета и порядка SHALL сохраняться согласованным последним снимком с существующими статусами сохранения, обработкой поздних ответов и повтором при ошибке. Уже отправленная запись SHALL продолжаться после закрытия popup.

#### Scenario: Дубликаты и перенос
- **WHEN** пользователь меняет символ одной из двух одноимённых записей, переименовывает и переносит её
- **THEN** эмодзи остаётся с этой записью и не меняет вторую

#### Scenario: Отмена preview
- **WHEN** перенос отменён после preview
- **THEN** исходный порядок восстанавливается вместе с цветами и эмодзи

#### Scenario: Быстрые изменения и ошибка
- **WHEN** пользователь быстро меняет символ, общий переключатель и цвет, а сохранение завершается ошибкой
- **THEN** popup сохраняет последний черновик, сообщает ошибку и позволяет повторить весь снимок без отката к позднему ответу

#### Scenario: Закрытие после отправки
- **WHEN** popup закрывается после отправки изменения worker
- **THEN** при успешной записи последнее состояние доступно после повторного открытия
