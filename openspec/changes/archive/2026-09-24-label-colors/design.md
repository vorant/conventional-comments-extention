## Context

Мотивация и границы продукта — в proposal.md. Сейчас popup и content script отдельно нормализуют `ccLabels` как массив строк в `chrome.storage.sync`. Popup сохраняет список напрямую и подавляет ошибки записи; drag preview переставляет строки в памяти. Content script пересоздаёт панели при изменении списка. Профили хранятся отдельно в local, их полный CSS применяется через один style-элемент.

Design необходим: меняются общая модель данных, сохранение popup и контракт каскада CSS. Прежние specs обещают отсутствие оформления при пустом CSS; согласованное решение пользователя заменяет это правило приоритетом цветов labels. Delta-specs должны явно отразить исключение.

## Goals / Non-Goals

**Goals:** единая интерпретация labels в popup и content script, сохранность существующих данных, независимые цвета даже у одинаковых названий, предсказуемый приоритет цветов и проверяемое автосохранение.

**Non-Goals:** иконки labels, прозрачность в пикере, отдельные ручные настройки текста/фона/рамки, цвета по сайтам, новый механизм синхронизации между устройствами или гарантии объединения конкурентных правок с разных устройств.

## Decisions

### 1. Общая модель и совместимость

Добавить небольшой общий модуль `src/label-settings.js` без зависимостей: defaults, нормализация, палитра, чтение и формирование снимка. Подключить до popup/content script во всех путях: popup.html, manifest, динамическая регистрация и executeScript в worker.

Предлагаемая новая запись sync: `ccLabelSettings: {schemaVersion: 1, items: [{text, color}]}`, где color — нормализованный шестизначный HEX. Массив записей сохраняет цвет при переносе и переименовании; одинаковый текст не объединяет элементы. Отдельные id пока не нужны: операции popup адресуют записи в текущем массиве, а сохраняется полный снимок.

Если новой записи нет, читать прежний `ccLabels`: известные точные названия после прежней trim-нормализации получают палитру, остальные — нейтральный цвет. Пустой список остаётся пустым. Чтение само не записывает миграцию. При первом редактировании сохранить новую запись и строковую проекцию `ccLabels` одним вызовом storage.set. Новая версия использует новую запись как источник истины; строковая проекция позволяет прежней версии продолжить показывать labels при откате. Неизвестную schemaVersion не перезаписывать автоматически: показывать ошибку в popup; для чтения панели допустима старая строковая проекция. Повреждённый цвет в известной схеме заменять нейтральным независимо от текста, не удаляя label.

Альтернативы: заменить строки объектами в прежнем ключе — старый content script отфильтрует весь список; хранить карту по тексту — цвет потеряется при переименовании и одинаковые названия нельзя настроить независимо. Поэтому выбран новый ключ с проекцией для прежней версии.

### 2. Палитра и получение оттенков

Один базовый цвет задаёт цветовую группу. Начальные HEX — проектные значения, визуально приближённые к изображению, не точное извлечение пикселей:

| Label | Базовый цвет |
|---|---|
| praise | #238636 |
| nitpick | #6B7280 |
| suggestion | #0969DA |
| issue | #CF222E |
| todo | #BC4C00 |
| question | #8250DF |
| thought | #7061AA |
| chore | #78665C |
| note | #087E9B |
| Новый label | #6B7280 |

Для новых записей, созданных кнопкой Add, всегда использовать нейтральный цвет, даже если пользователь ввёл стандартное название; палитра по имени нужна только для defaults и чтения прежних строк. Переименование уже существующей записи не меняет её цвет.

Получать непрозрачную светлую/тёмную заливку и оттенок рамки смешиванием базового RGB с поверхностью соответствующей темы. Подбирать яркость текста до контраста не ниже 4.5:1 к сгенерированной заливке; проверить чёрный, белый, жёлтый и малонасыщенные цвета. HEX хранится исходным выбором пользователя, производные оттенки не записываются. Расчёты в JS сохраняют Chrome 102 и не требуют новых CSS color API.

Тема popup берётся из существующего data-theme. На странице ревью ориентироваться на объявленную сайтом color-scheme (computed style контейнера редактора), при отсутствии однозначного значения — prefers-color-scheme. Пересчитывать при смене системной схемы и наблюдаемых атрибутов темы сайта на html/body; не связывать тему сайта с переключателем popup. Для сайта без объявления темы fallback следует системе, но непрозрачная пара текст/фон сохраняет собственную читаемость.

### 3. Popup и сохранение

В строке оставить drag handle и поле текста, перед корзиной добавить компактный нативный `input type=color`. Его текущая заливка служит образцом, доступное название содержит текст label. Отдельный HEX-input и отдельный picker для новой строки не нужны: после Add цвет выбирается в появившейся строке. Сохранить клавиатурный доступ и не начинать drag при взаимодействии с пикером.

События пикера обновляют draft сразу. Снимки текста, порядка и цвета проходят через последовательную запись, с объединением ещё не отправленных промежуточных снимков, чтобы движение в пикере не исчерпывало квоту sync. Статус «Сохранение… / Сохранено / ошибка» относится к последней версии; новая правка или кнопка повтора после ошибки повторяет последний снимок. Закрытие popup не должно отменять уже переданную запись: очередь выполняется в worker, аналогично существующей очереди профилей, с отдельной командой для полного снимка labels и проверкой отправителя. Во время ошибки draft сохраняется в открытом popup; успешное сохранение подтверждается только после storage.set.

Альтернатива прямой записи на каждый input сохраняет нынешние гонки и скрывает quota errors. Нативный picker выбран вместо стороннего компонента, чтобы не добавлять библиотеку и отдельный диалог.

### 4. Приоритет над CSS профиля

Применять рассчитанные `color`, `background` (непрозрачная заливка без gradient) и `border-color` к самой кнопке через CSSOM с приоритетом important. Это даёт приоритет над обычными и important-правилами CSS профиля, включая hover/focus и сохранённые старые стили. Для управляемых цветов исключить переходы, способные временно показать цвет из профиля; проверить это в реальном Chrome. Не вставлять текст label или произвольную строку цвета в HTML/CSS-селекторы.

Остальные свойства — геометрия, шрифт, ширина/тип рамки, outline, видимость — остаются у CSS профиля. Даже пустой CSS не отключает цветовые свойства labels, но стандартная геометрия скрытым слоем не возвращается. Если пользователь скрыл кнопку, добавил псевдоэлемент или убрал рамку через border-style, раскраска не отменяет это: обещание касается собственных цветовых свойств кнопки, не произвольного визуального перекрытия.

Применять цвет также к новым динамическим панелям. При изменении только цветов обновлять существующие кнопки на месте без потери фокуса и текста комментария; изменение текста/порядка может использовать существующую перестройку. Цвета уходят вместе с панелью при смене профиля/маски и отзыве доступа. Не менять стили диагностики.

Альтернатива переменных только в стандартном CSS отвергнута пользователем: сохранённый пользовательский или пустой CSS тогда оставляет кнопки без цветов.

### 5. Сброс профиля и документация

Цвета принадлежат общему списку labels. Оба сброса профиля не меняют их. В подсказке options, README и docs/site-profiles.md явно указать, что редактор CSS больше не переопределяет цвет текста/фона/рамки labels. Архив прежнего change не переписывать: новая delta корректирует действующий контракт.

## Risks / Trade-offs

- Частые события picker и квоты sync → очередь worker объединяет ожидающие снимки, ошибки видимы, тестируются задержки и закрытие popup после отправки.
- Изменение каскада ломает прежние CSS-настройки цвета → это согласованный приоритет; исходный пользовательский CSS остаётся без изменений.
- Неполные данные темы сайта → документированный fallback на системную схему, собственная контрастная непрозрачная заливка; проверить независимые темы popup и сайта.
- Старые версии на другом устройстве не знают новой записи → строковая проекция обеспечивает откат отображения, но двустороннее объединение правок старой и новой версий не поддерживается.
- DOM-моки не рассчитывают CSS и нативный picker → дополнить node-тесты браузерной проверкой реального каскада, фокуса и обеих тем.

## Migration Plan

1. Добавить общий модуль и совместимое чтение до переключения потребителей; покрыть прежние строки и пустой список.
2. Подключить новый ресурс ко всем способам внедрения и обновить регистрацию worker при смене списка файлов.
3. При первом редактировании сохранить новую запись и строковую проекцию; не мигрировать CSS профилей и тему.
4. После обновления unpacked extension перезагрузить расширение и старые вкладки. Стандартные labels сразу цветные без посещения popup и без восстановления CSS.
5. При откате прежняя версия читает строковую проекцию и игнорирует цвета. Правки в старой версии не объединяются с сохранённой новой записью при повторном обновлении; это ограничение описать в документации.
