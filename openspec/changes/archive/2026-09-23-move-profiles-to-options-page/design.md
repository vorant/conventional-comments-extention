## Context

См. proposal.md для мотивации. Форма находится в src/popup.html, её логика уже выделена в profile-settings.js. Popup.js управляет labels и темой. Worker последовательно сохраняет профили и открывает popup.html?profile=… из диагностики. Изменение пересекает manifest, обе страницы и маршрутизацию, поэтому требует общего дизайна.

## Goals / Non-Goals

**Goals:** сохранить ключи хранилища, протокол сообщений worker и защиту от поздних ответов; разделить оформление popup и полноразмерной формы.

**Non-Goals:** новые поля и профили, перенос labels на страницу настроек, изменение адаптеров сайтов, сборщик и зависимости, миграция данных.

## Decisions

1. Зарегистрировать src/options.html через options_ui с open_in_tab: true. Gear вызывает chrome.runtime.openOptionsPage(); Chrome управляет открытием или фокусировкой страницы. Встроенное окно chrome://extensions менее удобно для развёрнутой формы, а простая незарегистрированная HTML-страница не даёт штатного входа через настройки Chrome.
2. Перенести существующую форму и подключение site-profiles.js / profile-settings.js в options.html. Убрать details и зависимость скрипта от его open. Сохранить идентификаторы полей, состояния черновиков, валидацию и очередь worker. Не дублировать форму в двух местах, чтобы не поддерживать два интерфейса одной операции.
3. Для диагностики сохранить cc-open-settings и проверку известного id в worker, но открывать src/options.html?profile=<id> через tabs.create: openOptionsPage не принимает параметр выбора профиля. Неиспользуемый параметр tab убрать. Прямой переход без известного profile выбирает GitHub. Повторное использование вкладок диагностики не требуется; этот путь может создавать отдельную вкладку, как сейчас.
4. Выделить общие цветовые токены, шрифт и стили icon-button в общий CSS, геометрию страницы — в options.css. Форма по центру с ограниченной шириной и адаптацией к узкому окну, поля друг под другом. Gear справа от темы использует поставляемый шрифт и доступные title/aria-label. Не растягивать существующий компактный popup.css на полноразмерную страницу.
5. Использовать существующий ключ темы. Небольшой общий модуль темы для popup и options исключает различие defaults и обработки хранилища. Страница options слушает storage.onChanged и меняет только тему, не перерисовывая форму. Предлагаемый default: отдельный переключатель темы на options не добавляется. Выбор темы остаётся в popup.
6. Новая область options-page владеет формой, восстановлением, доступом, автосохранением и темой страницы. В site-profiles остаются состав/применение/совместимость профилей и размещение панели. Для переноса автосохранения используется REMOVED в исходной области и ADDED в новой; смешанные требования разделяются через полные MODIFIED-блоки. Архивы не редактируются. docs/site-profiles.md остаётся технической документацией о профилях, в нём обновляется путь к форме.

## Risks / Trade-offs

- Потеря пользовательского жеста при запросе доступа → сохранить непосредственный вызов permissions.request в обработчике кнопки; проверить в Chrome на новой странице.
- Поздние ответы при переключении профиля → переиспользовать текущую версионность состояния и существующие тесты автосохранения.
- Долгоживущая вкладка может одновременно существовать с другой вкладкой настроек → сохранить текущую последовательную очередь записей; одновременное редактирование одного профиля разрешается последней записью, слияние черновиков не входит в изменение.
- DOM-стенд не проверяет геометрию и настоящий Options API → дополнить тесты ручной проверкой unpacked extension в обеих темах, переходов и запроса разрешения.

## Migration Plan

Добавить страницу, переключить оба входа и убрать форму из popup одним изменением. Ключи и формат данных не менять; после reload расширения ранее сохранённые профили доступны на новой странице. Обновить README и docs/site-profiles.md, выполнить проверки, синхронизировать delta specs и архивировать change. Откат к предыдущей версии интерфейса не требует миграции хранилища.
