## Context

Мотивация и границы описаны в proposal.md. Текущий MV3 manifest объявляет service worker, статическое подключение на GitHub, optional host permissions, popup и options. `background.js` загружает зависимости через importScripts, регистрирует разрешённые сайты через scripting, обменивается сообщениями с вкладками и сериализует сохранение labels. Labels и тема используют storage.sync, профили — storage.local. Тесты node:test проверяют Chrome API через заглушки и не доказывают совместимость Safari.

На машине обнаружен Safari 27.0; активный developer directory — CommandLineTools. Это наблюдение среды, не доказательство доступности UI временной установки или поддержка всех прежних версий Safari. Дизайн необходим из-за пересечения packaging, permissions, storage и фонового жизненного цикла.

Документация Apple, проверенная при подготовке:
- [Running your Safari web extension](https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension): временная загрузка папки без Xcode, удаление при выходе либо через 24 часа.
- [Browser compatibility](https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility): поддерживаются chrome/browser и callbacks/Promises; storage.sync хранит данные без синхронизации; динамические content scripts доступны начиная с Safari 16.4. Это не означает поддержку нашего способа установки в Safari 16.4.

## Goals / Non-Goals

**Goals:** общий источник поведения и ресурсов, отдельный воспроизводимый пакет, минимальные адаптации и проверяемая локальная процедура.

**Non-Goals:** универсальный browser framework, полифилл всех API, сборщик фронтенда, копия src для Safari, перенос пользовательских данных между браузерами. Объём платформ и распространения см. proposal.md.

## Decisions

### 1. Общие исходники и производный manifest

Оставить корневой manifest Chrome и src каноническими. Небольшой Node-скрипт без зависимостей создаёт `dist/safari/` из manifest и разрешённого списка ресурсов, убирает minimum_chrome_version и применяет только проверенные Safari-различия. Генерация не включает .git, тесты, OpenSpec и служебные файлы; очищает только собственный output. Папка результата игнорируется git. Порядок content scripts, локальные vendor assets и лицензии сохраняются.

Ручная поддержка второй копии src отклонена из-за расхождения исправлений. Система сборки с зависимостями не нужна для копирования файлов и преобразования JSON.

### 2. Использовать поддерживаемые API, адаптировать подтверждённые различия

Сохранить chrome namespace, Promise-вызовы, storage.sync/local и схемы данных. Не заменять sync на local только из-за названия API: Apple поддерживает хранение, а такая замена потребовала бы менять обработку onChanged и рисковала бы данными Chrome. Не обещать облачную синхронизацию Safari.

Сначала проверить MV3 worker с importScripts, асинхронные ответы сообщений, очередь сохранения после закрытия popup, options page и startup. Если необходима адаптация, вынести только соответствующую браузерную операцию в небольшой общий модуль и загрузить его до потребителей во всех контекстах. Не менять архитектуру фона без воспроизводимой ошибки Safari. При необходимости отдельного loader его выбирает производный manifest, а логика обработчиков остаётся общей.

### 3. Адресные разрешения и динамическая регистрация

Сохранить узкий обязательный GitHub host и optional hosts остальных профилей. Запрашивать доступ из пользовательского действия. Проверять фактические permissions в Safari даже для GitHub: manifest не доказывает согласие пользователя. Сохранять регистрацию разрешённых сайтов, очистку и уведомление доступных вкладок при отзыве. Проверить getRegisteredContentScripts, persistAcrossSessions, tab URL visibility, permission events и отказ регистрации. Ошибки не маскировать успешным состоянием. Не использовать обязательный доступ ко всем сайтам как обход несовместимости.

### 4. Временная установка как первый локальный путь

План предлагает Developer settings → Add Temporary Extension для отдельной папки. Это допущение для review: пользователь подтвердил локальный macOS, но не выбирал временный жизненный цикл. Ограничение вынесено в proposal и спецификацию, чтобы его можно было изменить до реализации. Постоянная локальная установка через native app не входит в этот план.

Перед реализацией подтвердить наличие этой команды в установленном Safari. Если её нет, не подменять путь скрыто Xcode-проектом: зафиксировать блокировку и пересмотреть способ установки с пользователем. Документировать только реально проверенные версии, не назначать предполагаемый minimum Safari.

Общие specs требуют сохранения настроек между перезапусками браузера. У временной установки завершение Safari является удалением расширения, поэтому Safari-spec явно ограничивает гарантию активной установкой. Chrome-контракт не изменяется. Проверить и записать фактическое поведение данных при reload и повторном добавлении, не обещая сохранность после удаления.

## Risks / Trade-offs

- Временная установка неудобна для ежедневного использования → явно описать повторное добавление и границы сохранности; постоянную упаковку согласовывать отдельно.
- Заглушки не отражают Safari permission/lifecycle → дополнить автоматические тесты реальной проверкой GitHub и локальных editor fixtures, не выдавать fixtures за полноценный тест GitLab/Bitbucket.
- Popup может закрыться во время сохранения, worker — завершиться → проверить подтверждённые записи после перезапуска фона, ошибки API и обновление нескольких панелей.
- Safari UI и WebKit могут иначе отображать popup, drag-and-drop, шрифт и emoji picker → ручная проверка размеров, обоих themes, клавиатуры и локальных ресурсов.
- Общие адаптации могут повредить Chrome → сохранять исходный manifest и прогнать существующие тесты и Chrome smoke test.

## Migration Plan

1. Подтвердить временную установку и конкретные API на текущем Safari; зафиксировать версии и результаты.
2. Добавить генерацию пакета, необходимые небольшие адаптации и тесты; сформировать пакет повторно и проверить его полноту.
3. Локально загрузить, проверить сценарии и документировать ограничения на английском в README/отдельной инструкции.
4. Chrome-данные не мигрируют; Safari начинает с defaults. Откат локального Safari — удалить временное расширение, не затрагивая Chrome.
5. После реализации и проверок синхронизировать specs и архивировать change. Непроведённую Safari-проверку не считать завершённой задачей.
