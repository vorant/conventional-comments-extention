## Context

См. proposal.md для мотивации. Makefile имеет автоматически формируемую help и Chrome ZIP target package. scripts/package-firefox.js уже создаёт очищенную папку с адаптированным manifest и LICENSE. npm-зависимостей нет. Тест Firefox packaging проверяет полноту и повторяемость папки, сохранность соседних пакетов и исходников.

## Goals / Non-Goals

**Goals:** единая подготовка Firefox-ресурсов, воспроизводимая установка инструментов, явные ошибки команд и разделение выходных файлов разных браузеров.

**Non-Goals:** бандлинг исходников, подпись, публикация, автоматическая проверка авторизованного GitHub, изменение прежних результатов браузерных проверок, гарантированная побайтовая идентичность ZIP timestamps.

## Decisions

1. Использовать локальный web-ext из devDependencies, точную версию и lockfile; установка через npm ci. Версию выбрать при реализации по engines опубликованного пакета и доступному поддерживаемому Node.js, записать требования в документацию. Глобальная установка и автоматическое скачивание через npx не нужны: отсутствие инструментов должно давать ошибку с подсказкой npm ci. Добавить node_modules в .gitignore.

2. Make targets делегируют npm scripts. build-firefox вызывает существующий package:firefox, который по-прежнему только готовит папку. lint-firefox, run-firefox и package-firefox сначала подготавливают актуальную папку; последовательность задаётся явно, включая make -j. Проверка и упаковка используют именно dist/firefox, а не Chrome manifest в корне.

3. lint запускает web-ext lint. Ошибки дают ненулевой exit code и останавливают зависимые операции; предупреждения показываются без подавления и не считаются ошибками автоматически. package-firefox сначала проверяет пакет, затем вызывает web-ext build с выходом dist/conventional-comments-firefox-<manifest.version>.zip. Версия берётся из manifest, не дублируется вручную. Пересборка заменяет тот же Firefox ZIP без устаревших файлов. Выход ZIP расположен вне dist/firefox, чтобы не попасть внутрь следующего архива. Не включать node_modules, тесты, tooling или пакеты других браузеров.

4. run-firefox вызывает web-ext run после подготовки и lint. Использовать отдельный временный профиль по умолчанию, без изменения пользовательского профиля; предусмотреть FIREFOX_BIN для явного пути к исполняемому файлу с пробелами. Не обещать наблюдение за src: web-ext наблюдает подготовленную dist/firefox. Для первого этапа документировать повторный запуск run-firefox после изменения исходников; отдельный watcher копирования не добавлять.

5. Сохранить поведение make package и npm run package:safari. Уточнить описание package в help как Chrome ZIP, перечислить новые targets, зависимости, формат результата и временность запуска в README и docs/firefox.md. Подпись не подразумевается наличием ZIP.

Альтернатива ручной ZIP-упаковки без web-ext проще по зависимостям, но не даёт проверку Mozilla и запуск одной командой — пользователь выбрал полный набор web-ext. Переименование package:firefox в команду ZIP сломало бы текущую инструкцию, поэтому сохраняется прежний смысл.

## Risks / Trade-offs

- Новые требования Node.js и сеть при установке → точная версия, lockfile, документированный runtime и npm ci; сеть не нужна для скачивания инструмента при каждом запуске.
- Linter обнаружит существующие проблемы → исправить ошибки упаковки/метаданных в текущем объёме, предупреждения перечислить; изменения поведения расширения согласовать отдельно, не скрывать диагностику.
- Запуск браузера не доказывает работу PR editor → проверить временную загрузку и открытие UI; прежние непроверенные GitHub-сценарии не отмечать пройденными.
- Параллельная сборка и устаревший dist → использовать последовательную цепочку внутри каждого действия и тестировать свежий исходник при повторной упаковке.

## Migration Plan

Добавить dev tooling и команды, проверить чистую установку, lint, ZIP и запуск Firefox, обновить инструкции. Пользовательские данные не мигрируют. Откат tooling не меняет формат расширения и оставляет прежнюю команду подготовки папки доступной.
