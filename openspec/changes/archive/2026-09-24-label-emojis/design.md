## Context

См. proposal.md о цели. Сейчас `CCLabels` хранит записи `{text,color}` в `ccLabelSettings` schemaVersion 1 и строковую проекцию `ccLabels`. Worker объединяет снимки в очередь; popup отправляет только items. Content script получает общие данные и создаёт кнопки, editor-adapters сам собирает `<label>: `. Проект — unpacked MV3 без сборщика; ZIP включает весь src. Изменение затрагивает несколько модулей и формат хранения, поэтому требуется этот design.

## Goals / Non-Goals

**Goals:** единое построение отображаемого label и вставляемого префикса; сохранение Unicode-последовательностей; автономный готовый пикер, не требующий глобальных шрифтов.

**Non-Goals:** собственный каталог или поисковый движок, внешние картинки и CDN, обработка старых опубликованных комментариев, синхронизация предпочтений между разными людьми, раскраска опубликованного Markdown, изменение механизма отправки комментариев.

## Decisions

### Локальный готовый компонент

Использовать `emoji-picker-element` с локальным русским каталогом `emoji-picker-element-data` и русским i18n. Документация поддерживает локальный dataSource, native Unicode в событии emoji-click и отдельный перевод интерфейса: https://github.com/nolanlawson/emoji-picker-element . Поставить готовые ES-модули и все транзитивные runtime-ресурсы в src/vendor, зафиксировать точные версии, происхождение, лицензии и способ обновления. Версию выбрать и проверить при интеграции на совместимость с Chrome 102 и MV3; не повышать minimum_chrome_version молча. Пикер загружается только popup, content script не получает каталог. Не использовать стандартный CDN dataSource даже для первой загрузки. Сборщик и React не нужны; собственный пикер противоречит запросу.

Один переиспользуемый пикер открывается отдельным внутренним представлением popup для выбранной записи: название label, поиск/категории готового компонента, «Без эмодзи», возврат. Сохранять draft, закрывать по Escape, возвращать фокус; управление пикером исключить из drag. При удалении/перестроении целевой записи закрывать выбор, не применять его к другой строке. Интерфейс и данные поиска — русские; английский поиск не является обязательным критерием. Ошибка загрузки показывает сообщение и повтор, сохраняя доступ к остальным настройкам.

### Целостный снимок версии 2

Хранить `{schemaVersion:2, emojisEnabled:true, items:[{text,color,emoji}]}` в ccLabelSettings. emoji — строка Unicode либо пустая строка как явное отсутствие. Из старых строк и v1 назначать defaults по точному имени; пользовательские названия без символа. В v2 пустое/отсутствующее/некорректное значение не превращать обратно в default. Новая запись всегда с emoji пустой, даже с известным названием. Переименование не меняет emoji; дубликаты независимы. Нормализация допускает один emoji grapheme cluster, включая ZWJ, variation selectors, флаги и тон кожи, исключает управляющий текст, HTML и произвольные строки; не обрезать через charAt или один code point. Проверку строить на поддерживаемых Unicode-средствах Chrome 102 с тестами последовательностей.

Расширить CCLabels и протокол cc-save-labels до полного снимка настроек. Worker сохраняет данные и ccLabels-проекцию в одной операции через существующую очередь; сравнение снимков, retry и версия ответов учитывают общий флаг. Независимое хранение флага отвергнуто из-за риска несогласованной записи. Большой каталог остаётся ресурсом, не попадает в storage.sync. Тема и профильный CSS остаются отдельными настройками.

### Общий формат и обновление

Общий helper формирует отображаемую строку `<emoji> <text>` либо `<text>`; префикс добавляет `: `. Передавать готовый префикс адаптерам, чтобы textarea и rich-text не расходились. Unicode вставлять как текст, без shortcodes, HTML, Nerd Fonts или ресурсов chrome-extension. UTF-16 offsets использовать для браузерной установки курсора, включая весь составной символ. У уже стоящего идентичного полного префикса не создавать дубль. Другой префикс не распознавать и не удалять: сохранить текущую семантику добавления перед прежним содержимым.

В content script хранить полное актуальное состояние. Изменение символа/флага обновляет текст существующих кнопок и данные для клика без пересоздания редактора, изменения выделения или фокуса. Смена флага сама не исправляет черновик. При отключении общий список в popup всё ещё показывает выбранные символы для редактирования. Сбросы профилей не трогают настройки labels.

## Risks / Trade-offs

- Разный рендеринг Unicode и отсутствие новых эмодзи на старой ОС → системный fallback, штатная фильтрация поддержки в пикере; не обещать одинаковый рисунок у всех читателей.
- Размер каталога и IndexedDB при первом запуске → ленивый singleton, локальные ресурсы; проверить первый запуск без сети и упаковку ZIP.
- CSP и браузерная совместимость стороннего компонента → проверить установленный MV3 popup, сетевые запросы, консоль и заявленный минимум до принятия интеграции.
- Частичная миграция/квота → единый снимок, защитить неизвестные версии и текущий черновик, повторять через worker.
- Изменение текста формата комментария → общий переключатель возвращает прежний формат; старые публикации не переписываются.

## Migration Plan

1. Добавить чтение legacy и v1 без записи при простом просмотре; v2 сохранять при первом явном изменении, не теряя цвета, дубликаты и пустые списки.
2. Обновить worker, popup, адаптеры и content script согласованно; после обновления перезагрузить расширение и открытые страницы.
3. При откате старая цветовая версия не понимает v2: автоматический downgrade не выполнять. Для ручного отката с сохранением цветов сначала экспортировать настройки и преобразовать v2 в v1 с text/color; старый строковый потребитель использует ccLabels. Указать это ограничение в документации.
4. После тестов и приёмки синхронизировать delta specs и архивировать change. Публикация тестового комментария в чужом PR не входит в проверку: использовать preview/локальную fixture и среду без content script.
