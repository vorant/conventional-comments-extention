## Context

Мотивация и границы — в proposal.md. Интерфейс состоит из HTML и обычных JS без сборщика. Текст распределён по popup/options, общему theme.js, моделям, worker и адаптерам; часть ошибок достигает UI через error.message. Пикер загружается лениво из локального emoji-picker-element 1.29.1, с ru_RU.js и ru/cldr-native каталогом emoji-picker-element-data 1.8.0. Тесты проверяют буквальные русские подписи, русский каталог и SHA-256 vendor-файлов.

Design нужен, поскольку перевод пересекает несколько контекстов исполнения, поставку каталога и существующие контрактные тесты.

## Goals / Non-Goals

**Goals:** согласованная английская терминология во всех контекстах; доступность и offline-поиск; проверяемое отсутствие русских строк, поставляемых для UI; сохранность пользовательского содержимого и поведения.

**Non-Goals:** архитектура многоязычности, chrome.i18n, переключатель языка, перевод пользовательских данных и сайтов, новые зависимости или обновление версии пикера. Переработка README, описание магазина и публикационные скриншоты — следующий change. Русскоязычные OpenSpec-артефакты и исторические протоколы не являются интерфейсом.

## Decisions

### Перевод на месте без слоя локализации

Заменить строки в существующих HTML/JS и manifest, установить lang="en" в popup.html/options.html. Сохранить идентификаторы DOM, классы, ключи storage, типы сообщений и порядок загрузки. Общий каталог переводов и chrome.i18n сейчас добавили бы зависимости между worker и страницами без требования переключения языка; прямой перевод минимален для небольшого одноязычного проекта.

Пройти все поставляемые пользователю строки: title, placeholder, aria-label, title-подсказки, live regions, статусы, настройки темы, собственные исключения моделей и worker, ошибки размещения/вставки. Английские формулировки должны объяснять прежнюю причину и доступное действие. Нативный color picker, разрешения, HTML validation и текст внешних исключений Chrome/ОС могут зависеть от локали системы; не подменять их вымышленной диагностикой и не обещать перевод неподконтрольного UI.

### Согласованные названия

| Назначение | Английский текст |
|---|---|
| Переход из popup | Settings |
| Заголовок options | Site settings |
| Поля профиля | Profile; Site URL; Pages (one path per line); Editor CSS selector; Panel position |
| Размещение | Above editor; Below editor |
| CSS | Panel styles; Panel and button CSS; Reset styles |
| Полный сброс / доступ | Reset profile; Allow site access |
| Диагностика | Open profile settings; Close |
| Эмодзи | Show and insert emoji; No emoji; Back; Retry loading |
| Автосохранение | Saving…; Saved; Retry saving |
| Тема | Switch to light theme; Switch to dark theme |

Доступные имена выбора цвета и эмодзи включают неизменённый текст текущего label; для пустого имени использовать английское unnamed. Кнопка эмодзи остаётся слева от текстового поля после ручки переноса. При необходимости поправить перенос английских подписей в существующем CSS без редизайна.

### Локальный английский пикер

Поставить оригинальный i18n/en.js из той же версии компонента и en/cldr-native/data.json из той же версии данных как en.json. Передавать locale="en", английский i18n и явный chrome.runtime.getURL для dataSource; не полагаться на CDN-default даже если он английский. Удалить неиспользуемые ru_RU.js и ru.json из поставки, обновить checksums.json и src/vendor/README.md, сохранив лицензии и неизменённые runtime-модули.

Использование locale en создаёт отдельный индекс английского каталога; русская IndexedDB от прежней версии не должна служить источником поиска. Её не требуется удалять вручную. Избранное и тон кожи внутри стороннего пикера могут начать новую локальную историю; выбранные emoji записей и emojisEnabled остаются в ccLabelSettings и не меняются. Это отличается от пользовательских labels: их миграция не нужна. Альтернатива — переводить русский JSON вручную — отвергнута в пользу готового каталога с проверяемым происхождением.

### Проверка перевода и поведения

Обновить существующие ожидаемые UI-строки в popup/profile/worker/model/adapter тестах. Проверить английские сообщения при ошибках, неизвестных схемах, отказе доступа, загрузке/retry пикера и поздних ответах, сохранив поведенческие assertions. Проверки отсутствия кириллицы ограничить поставляемыми собственными UI-строками, HTML и manifest: не запрещать Unicode в пользовательских labels, fixtures, комментариях к коду или документации.

Vendor-тест проверяет английские ресурсы, их SHA-256, локальную полноту импортов и отсутствие русского каталога в ZIP. В установленном Chrome проверить новый профиль offline, поиск light bulb → 💡, клавиатуру и Escape, обе темы, доступность длинных подписей, статусы options и диагностику на локальной review-fixture. Повторить на установке с сохранёнными русскими labels и профилями, включая существовавшую русскую IndexedDB, чтобы проверить переход на английский поиск без изменения данных. Приёмочные изображения могут оставаться временными: публикационные скриншоты не готовятся в этом change.

## Risks / Trade-offs

- Пропущенные редкие ошибки и aria-label → аудит всех перечисленных модулей и проверка динамических состояний, а не только стартового экрана.
- Более длинные подписи → браузерная проверка обеих тем при штатной ширине popup, сохранение keyboard focus и доступности действий.
- Случайный перевод labels или CSS → регрессия с кириллицей, Unicode, пустым списком, дубликатами и пользовательским CSS; не выполнять массовую замену в сохранённых данных.
- Английский UI при русской документации между двумя changes → осознанный промежуточный этап; подготовить документацию и скриншоты следующим change до публикации.
- Нативный UI остаётся на языке системы → при последующей подготовке магазинных скриншотов использовать английский профиль Chrome; не менять продукт ради изображения.

## Migration Plan

1. Перевести собственный UI и подключить английские ресурсы без изменения схем данных, прав и минимума Chrome.
2. Обновить тесты/контрольные суммы и провести свежий offline-прогон, затем прогон обновления существующей установки; выполнить make package и проверить ресурсы ZIP.
3. После приёмки синхронизировать specs и архивировать change. Перезагрузить unpacked extension и страницы для обновления контекстов.
4. Откат состоит в возврате предыдущей версии файлов; пользовательское хранилище не конвертируется, предыдущая версия продолжит читать свои настройки и свой языковой индекс пикера.
