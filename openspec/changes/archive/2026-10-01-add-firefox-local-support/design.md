## Context

Мотивация описана в proposal.md. Текущий MV3 manifest запускает `src/background.js` как service worker; файл безусловно вызывает `importScripts`. Остальные контексты используют Promise-вызовы `chrome.*`, а `theme.js` смешивает callbacks и Promises. Фоновый код регистрирует content scripts для разрешённых профилей, хранит labels в storage.sync, профили в storage.local и отвечает на сообщения через callback с `return true`. Safari script уже копирует общие ресурсы в отдельную папку; тест проверяет полноту и повторяемость упаковки.

## Goals / Non-Goals

**Goals:** сохранить единую бизнес-логику, структуру хранения и существующие контракты UI; ограничить различия manifest, инициализацией и выбором API; не добавлять сборщик.

**Non-Goals:** универсальный compatibility framework, миграция данных между браузерами, изменение поведения редакторов, гарантия облачной синхронизации или восстановление удалённой временной установки.

## Decisions

1. **Отдельный производный manifest.** Новый `scripts/package-firefox.js` и npm command создают `dist/firefox`, копируют `src` и LICENSE, исключают скрытые служебные файлы и удаляют только предыдущий Firefox output с защитой от symlink родительской папки. Удаляются `minimum_chrome_version` и `background.service_worker`; задаются упорядоченные `background.scripts` и стабильный `browser_specific_settings.gecko.id` (предлагаемый локальный ID: `conventional-comments@vorant.local`). ID сохраняется между сборками и не означает подпись или регистрацию домена. Альтернатива — общий manifest с обоими background полями — увеличивает влияние на существующие установки.

2. **Общая фоновая логика с двумя способами загрузки.** В Firefox manifest перечисляет зависимости перед background.js. В worker зависимости загружаются через условный `importScripts`, доступный в этом контексте. Не дублировать background.js и не переписывать его текст при упаковке. Сохранить синхронную регистрацию слушателей и callback-протокол ответа на сообщения. Проверять перезапуск фонового контекста и подтверждённое сохранение labels.

3. **Явный выбор Promise API в каждом контексте.** Использовать локальную ссылку `globalThis.browser ?? globalThis.chrome` в обращающихся к API модулях без подмены глобальных объектов. Привести theme.js к совместимым Promise-вызовам, сохранив fallback и защиту от гонок. Проверить content-script.js, background.js, popup.js, profile-settings.js, emoji-picker.js и theme.js. Альтернатива — polyfill — добавляет зависимость, ненужную при имеющихся современных API. Простая замена имени `chrome` не достаточна из-за callback-кода темы.

4. **Не менять модель разрешений и хранения.** Сохранить явный пользовательский жест при запросе доступа, реальные проверки permissions, динамическую регистрацию и обработку отзыва. Стабильный ID нужен также для storage.sync; не обещать синхронизацию между Chrome и Firefox. Повторное открытие UI и Reload активной установки должны сохранять данные; удаление и последующая установка — отдельный недоговорённый браузером жизненный цикл.

5. **Проверять desktop на доступной macOS.** Это рабочее допущение по окружению пользователя. Записать фактические версии Firefox/ОС; не объявлять Android, старые версии или другие ОС проверенными. Локальный запуск через `about:debugging#/runtime/this-firefox`, выбор `dist/firefox/manifest.json`; после пересборки Reload расширения и обновление вкладки. Временная установка удаляется при перезапуске Firefox.

Документация платформы: [background](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background), [API](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API), [add-on ID](https://extensionworkshop.com/documentation/develop/extensions-and-the-add-on-id/), [temporary installation](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/).

## Risks / Trade-offs

- Различия Chrome callbacks и Firefox Promises → тесты с раздельными browser-only и chrome-only окружениями, включая тему и ошибки API.
- Моки не подтверждают поддержку браузером → ручная проверка загрузки, хранения, сообщений и разрешений; фиксировать непроверенные пункты, не отмечать их выполненными.
- Firefox DOM/редактирование могут отличаться → проверить вставку без потери текста, курсор, несколько редакторов и SPA на реальном GitHub; preview-профили не повышать до гарантированной поддержки.
- Изменения общих файлов влияют на Safari и Chrome → весь npm test, тест Safari packaging и smoke-проверки имеющихся установок.
- Временная установка может потерять данные после удаления → явно описать ограничение; стабильный ID не выдавать за гарантию восстановления.

## Migration Plan

Миграция пользовательских данных не нужна. Добавить адаптацию и упаковку, выполнить автоматические и браузерные проверки, затем опубликовать локальную инструкцию в репозитории. Синхронизировать delta specs и архивировать change только после завершения задач. Откат — удалить временную установку и вернуть общие изменения; исходные данные других браузеров не затрагиваются.
